# Concurrency

`libs::Concurrency` 提供单资源的非阻塞占用标记及 RAII 守卫，入口为 [AtomicFlagLock.hpp](AtomicFlagLock.hpp)。[cpkg.toml](cpkg.toml) 未声明其他包依赖；实现使用 C++ 标准库 `<atomic>`，不是 RTOS 互斥锁或等待队列。

## 获取与生命周期

- `lock()` 仅尝试一次：从空闲切换到占用时返回 `true`，已占用时返回 `false`，不会等待。失败后不能调用 `unlock()`；释放只应由成功获取者执行。
- 成功获取使用 acquire，释放使用 release；只有所有访问者遵守同一把锁的获取/释放协议，才能据此保护共享数据。`is_locked()` 只是瞬时观察，不等于获得访问权。
- `AtomicFlagGuard` 借用锁，构造时尝试获取；必须检查其布尔结果后才进入受保护区域。析构只释放本守卫成功获取的锁。锁对象必须比守卫及所有使用者活得更久，不能在仍有访问者时销毁。
- 锁不记录线程身份，也不支持递归计数。重复获取会失败；接口不会阻止非持有者错误释放。守卫不提供可复制的所有权。

## 并发与 ISR 边界

实现没有自旋重试，也没有调度、超时、公平性或优先级继承。不能在 ISR 中反复等待被抢占任务持有的标记，否则任务无法恢复并释放。

底层是 `std::atomic_bool`，源码没有证明目标工具链的该类型为 lock-free，也没有屏蔽中断。因此不能仅凭包名或 `noexcept` 宣称 ISR 安全：宿主必须确认原子操作在目标上的实现、ISR 可调用性，以及成功获取后执行的代码本身是否适合该上下文。线程与 ISR 共用时，获取失败应由调用方按业务处理，而不是视为已进入临界区。

# traits

`traits` 是用于表达 C++ 对象特殊成员、构造访问权限与分配限制的小型头文件包，不是运行期类型检查器或 C++ concepts 集合。统一入口为 [traits.hpp](traits.hpp)，也可包含具体约束头文件。[cpkg.toml](cpkg.toml) 未声明其他包依赖。

## 约束的实际范围

这些类型通常作为基类参与派生类的特殊成员生成，但名称不能替代 C++ 的生成与访问规则：

- [NoCopy](no_copy.hpp)、[NoMove](no_move.hpp) 和 [NoCopyMove](no_copy_move.hpp) 通过删除对应特殊成员限制操作。删除移动成员还会影响隐式拷贝的生成，删除拷贝成员也会影响隐式移动；不能把单个名字理解为“另一种操作必然保留”。派生类自行实现特殊成员时仍需审查实际语义。
- [NoHeap](no_heap.hpp) 删除类作用域的普通 `operator new/new[]`，限制通常的类分配表达式；不是禁止任何堆内存来源的证明，也不提供内存池或 placement 构造接口。显式全局分配等路径不受这一名称保证。
- [NoDelete](no_delete.hpp) 只有受保护析构函数；[NoStack](no_stack.hpp) 与 [InterfaceOnly](interface_only.hpp) 都只有受保护的默认构造和析构函数。这些访问限制约束的是基类自身，不能自动禁止派生类公开构造/析构、栈实例化或 `delete`。`InterfaceOnly` 没有纯虚函数或虚析构函数，不会自动建立多态接口的销毁契约。
- [NoDerive](no_derive.hpp) 自身标为 `final`，所以不能再继承它来“给另一个类型附加 final”；需要限制的业务类应直接使用语言的 `final`。
- [StaticOnly](static_only.hpp) 删除默认构造函数，不会检查成员是否都是静态成员，也不等同于删除所有特殊成员。

## 生命周期与集成边界

本包不持有业务资源、不执行资源释放，也不自动稳定外部缓存的地址。资源归属、工厂接口、销毁方式及回调持有期仍由消费类型定义。编译错误是使用被删除或不可访问成员时的主要反馈，不存在容量、空满或运行期错误返回。

这些约束本身不提供同步、原子性或 ISR 适配，也不能证明派生类无动态分配。用于硬件句柄、锁或回调对象时，应按消费类型的真实构造、访问和销毁路径选择约束，不能从 trait 名称推导线程安全或内存安全保证。

# 电机 PID 控制器

`PIDMotor` 是带前馈与积分限幅的离散 PID 计算器，适合由宿主组织的位置环、速度环等控制循环；它本身不读取电机反馈，也不发送驱动指令。

## 接入与控制律

cpkg 包名为 `libs::PIDMotor`，见 [cpkg.toml](cpkg.toml)；manifest 未声明包依赖。公开入口为 [pid_motor.hpp](pid_motor.hpp)，算法见 [pid_motor.cpp](pid_motor.cpp)。本包随宿主集成，不独立构建。

每次 `calc(ref, fdb, ff)` 按以下顺序更新：

1. 计算误差 `e = ref - fdb` 与误差差分 `e - prev_error`。
2. 将 `Kp * e + Kd * (e - prev_error) + ff` 先夹到总输出上下限。
3. 积分状态累计 `Ki * e`，再夹到剩余幅值空间 `abs_output_max - abs(已限幅的 PD + FF)`。
4. 返回已限幅的 PD + FF 与积分项之和，并保存本次误差。

这是给积分项分配剩余输出空间的实现，不是反算式 anti-windup；当 PD + FF 已饱和时，积分可用空间为零。前馈使用输出单位，也参与第一次限幅。

## 周期、初始化与边界

- 没有 `dt` 参数；积分不乘采样周期，微分不除采样周期。调用方负责更新节拍，并把实际周期纳入离散 `Ki`、`Kd` 的选择。
- 目标与反馈需使用相同单位和方向；库不做角度环绕、误差滤波或输入有效性检查。
- 默认对象内的配置、历史和输出为零。自行创建 `Config` 时须初始化所有四个字段；配置结构本身没有字段默认值。
- 构造与 `setConfig()` 要求调用方提供有限、非负的 `abs_output_max`；二者不校验或修正它。负上限会破坏 `std::clamp` 所需的上下界顺序。`setOutputMax()` 则会先取参数绝对值，但也不验证非有限值。
- 零上限在有限输入下使 PD + FF 和积分均被夹为零。没有错误码、NaN/Inf 隔离或执行器故障状态。
- `reset()` 清空输入、误差历史、积分及输出，保留配置。复位后首次差分以零历史误差为基准。
- `setConfig()`、`setOutputMax()` 不复位积分和历史，也不立即重算最近输出；新参数在下一次计算中生效。切换控制对象或参数时，由宿主决定是否显式复位。

## 状态与资源归属

每个实例按值持有配置、积分与历史，不持有电机或外设资源。宿主负责反馈采集、周期调度、输出单位映射及安全停机。同一实例的计算、复位、配置修改和状态读取没有同步机制；跨任务或任务/ISR 共享时须由调用方串行化，不能将其视为驱动层安全限流器。

# Deque

`libs::Deque` 提供固定容量双端队列 `Deque<T, N>`，用于最近采样值、滑动窗口等。入口为 [Deque.hpp](Deque.hpp)；[cpkg.toml](cpkg.toml) 未声明其他包依赖。

## 存储与容量策略

- `N` 必须大于零，可用容量就是 `N`。所有 `T` 对象内嵌于容器，创建容器时一次性初始化；入队是对已有槽位赋值，不是按需分配或构造。
- 满时 `push_back()` 覆盖原队首并前移队首；`push_front()` 覆盖原队尾。它们没有失败返回，也不会扩容。需要保留全部数据时，应先检查 `full()` 并由上层选择策略。
- 空队列的两种 `pop` 都不做任何事。`pop` 和 `clear()` 只改变逻辑范围，不立即销毁槽位中的 `T` 或释放其持有的资源；槽位以后会被赋值覆盖，全部元素最终随容器销毁。
- 容器不主动申请动态存储，但 `T` 的构造和赋值可能申请内存。修改接口标为 `noexcept`，所调用的元素操作若抛出异常不会转化为错误码。

## 访问与遍历前提

`front()`、`back()` 必须在非空时使用。`std::size_t` 下标要求小于 `size()`；有符号下标支持 `[-size(), size())`，其中 `-1` 表示末元素。`at(int)` 与下标一样没有边界检查、异常或错误返回，不能按标准容器的检查式访问来使用。

`range(a, b)` 借用容器并保存逻辑索引，遍历半开区间，不复制元素。调用方必须保证区间中每个索引有效，且不在遍历中修改队列。当前迭代器解引用固定返回 `T&`，与 const 容器返回的 `const T&` 不匹配，不能把 const `range()` 当成已可用的只读遍历接口。

底层数组不扩容，但这不等于元素引用的业务含义稳定：前端插入/移除会改变逻辑索引，覆盖和槽位复用会改变已取得地址中的值，`clear()` 后旧引用不再代表有效队列元素。范围与引用不得超过容器生命周期；结构修改后应重新取得遍历范围与访问结果。

## 并发边界

队首、长度及元素都是普通对象，没有锁或原子发布协议。共享实例的读写、遍历与修改需要调用方串行化；线程与 ISR 直接并发访问也不受支持。在 ISR 独占或外部临界区中使用时，还必须确认 `T` 的构造/赋值等操作适合该上下文，不能仅凭固定容量推断 ISR 安全。

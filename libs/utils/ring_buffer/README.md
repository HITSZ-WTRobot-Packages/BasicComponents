# RingBuffer

`libs::RingBuffer` 提供 `libs::RingBuffer<T, Capacity, Overwrite>` 固定存储环形缓冲区，入口为 [RingBuffer.hpp](RingBuffer.hpp)。[cpkg.toml](cpkg.toml) 未声明其他包依赖；builder 约束使用 C++17 的类型特征。

## 存储、空满与生命周期

- `Capacity >= 2`，保留一个空槽区分空满，因此实际容量为 `Capacity - 1`。全部 `T` 槽位内嵌于容器，创建时已存在；标量槽位不保证预先清零。
- 默认 `Overwrite=false`：满时 `push` 返回 `false`，`emplace()` 返回 `nullptr`；失败的 builder 入队不会执行 builder。`Overwrite=true` 时满队列会先丢弃最旧元素，再接受新元素。
- 空时复制式 `pop(out)` 返回 `false`，不修改 `out`；指针式 `pop()`、`front()`、`back()` 返回 `nullptr`。
- 出队和 `clear()` 不销毁元素；`clear()` 仅复位索引，不清除存储内容。槽位以后被赋值或复用，所有槽位对象最终随容器销毁。容器不自行动态扩容，但 `T` 和 builder 仍可能分配内存。

## 写入发布与借用指针

builder 接受已有槽位的 `T&`、返回 `void`，调用结束后才前移写索引，不是 placement 构造。`emplace()` 则在返回槽位指针之前已经前移写索引，没有单独的提交动作；调用者必须在任何后续消费者访问之前完成填充，不能把它当作可并发的“预留后发布”接口，也不能读取槽位残留值作为新数据。

指针式 `pop()` 返回内部地址的同时就释放逻辑槽位，后续入队可以覆盖该地址；`front()`、`back()` 和 `emplace()` 返回的地址也都只是借用。不得跨槽位复用长期持有，或在容器销毁后访问。出队后需要稳定保存数据时使用复制到调用方对象的形式。本包没有迭代器。

入队、出队等接口标为 `noexcept`；元素赋值或 builder 抛出的异常不会变成失败返回。调用方应选择适合该错误模型的元素与 builder。

## 并发与 ISR 边界

索引使用 `volatile std::size_t`，不是 C++ 原子变量，也没有锁、内存屏障或临界区。`volatile` 不构成线程间数据同步，代码中的先写元素再更新索引也不是完整的并发发布协议；即使单生产者/单消费者，也不能据此宣称可直接跨线程或跨 ISR 使用。覆盖模式下生产者还会修改读索引。

共享实例必须由宿主提供覆盖整个操作及借用指针使用期的串行化。ISR 中只能在确认该保护方式、元素操作和 builder 均适用后使用；不能在被抢占任务持有的普通互斥锁上等待。固定容量和环形命名不代表 lock-free、线程安全或 ISR 安全。

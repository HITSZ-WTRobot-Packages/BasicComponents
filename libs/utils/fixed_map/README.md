# FixedMap

`libs::FixedMap` 提供小规模键到借用指针的映射 `FixedPointerMap<K, V, N>`。入口为 [FixedPointerMap.hpp](FixedPointerMap.hpp)；[cpkg.toml](cpkg.toml) 未声明其他包依赖。查找与插入的重复键检查都是线性扫描，不是哈希表。

## 容量与所有权

- 表内直接保存 `N` 个 `std::pair<K, V*>` 槽位，不动态扩容。应使用正容量；实现没有对零容量建立标准 C++ 数组的有效契约。
- 键按值保存，需要可默认构造、赋值并支持相等比较；这些键操作自身可能分配内存或抛出异常，容器不将其转为错误码。
- 值只是指针，表不创建、复制或删除 `V` 对象。被引用对象必须覆盖所有实际访问期；销毁表或移除注册不会销毁该对象。复制表也只是复制这些借用指针，不会转移对象所有权。
- 插入遇到重复键或容量已满都返回 `false`，不覆盖旧键值；返回值不区分这两种原因。允许保存空指针，因此 `find()` 返回 `nullptr` 既可能表示缺失，也可能是已登记的空值。

## 当前删除限制

当前 `erase()` 找到键后只减少长度，没有把末项搬到被删位置，与源码中“末项覆盖”的注释不同。删除非末项时，被指定的键仍可能被 `find()` 找到，而原末项会退出有效查找范围；返回 `true` 不能作为该键确已移除的保证。需要一般删除语义的注册表不能直接依赖此实现；这不是稳定顺序或无序删除的正常契约。

没有暴露表内迭代器或键槽位地址。`find()` 返回的是外部 `V` 对象指针，表内插入不会移动该对象，但也不会延长对象寿命；对象被外部销毁后指针即失效。

## 并发边界

表的长度与槽位都没有同步保护；查找也不能与修改直接并发。线程/ISR 共享时由宿主统一串行化，并保证借用对象不会在访问中被销毁。只有在独占或适当保护的调用中，且键操作与被引用对象访问本身适合当前上下文时，才可考虑在 ISR 使用，不能从固定容量推导安全保证。

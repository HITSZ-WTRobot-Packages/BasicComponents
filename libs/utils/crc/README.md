# CRC

`libs::CRC` 提供查表式 CRC 模板 `crc::CRCX<Bits, Poly, Init, Rin, Rout, XorOut>`，入口为 [crc.hpp](crc.hpp)。[cpkg.toml](cpkg.toml) 未声明其他包依赖；实现使用 C++17 的模板与内联静态编译期数据，不依赖 STM32 CRC 外设。

## 参数与算法前提

- 模板接受 8、16、24、32、64 位宽；24 位结果以 `uint32_t` 保存。多项式、初值及最终异或值均由调用方显式提供，没有默认 CRC 变体。多项式按源码的左移反馈表示填写，不包含隐含的最高次项；参数应处于所选位宽内。
- 每种模板实例有一张 256 项的编译期表。`Rin` 控制生成表项时对输入 8 位做反转，`Rout` 控制对表项结果做位宽反转；计算循环本身仍使用高字节索引和左移累加，并不按反射选项切换为低字节/右移递推。
- 因此，文件注释中的 MODBUS、Ethernet 等配置只是注释示例，不能据名称认定反射型配置符合对应标准。接入协议前必须用协议给定的已知校验向量核对，尤其是反射参数组合；本文不把该实现标作已经验证的通用标准 CRC。
- 当前掩码表达式对 32 位实例包含 `uint32_t(1) << 32`；在 STM32 常见的 32 位 `uint32_t`/`int` 环境中这是移位计数达到类型宽度的问题，不能将模板列出 32 位理解为该配置已可直接使用。此文档不修改算法实现。

## 输入、结果与资源

每次 `calc()` 都从 `Init` 开始，计算完应用 `XorOut` 并按位宽掩码；接口不暴露续算状态，不能把前一段的最终返回值直接当成下一段的内部累加状态。零长度输入返回掩码后的 `Init ^ XorOut`。

指针形式借用连续的 `len` 字节，只在调用期读取；非零长度必须提供有效且可读的地址。零长度不解引用输入指针。`std::array<uint8_t, N>` 形式可参与编译期求值。没有输入地址/长度检查、错误码或自动跳过帧尾校验字段；需要校验的范围、帧字段字节序及结果写回字节序均由协议调用方决定。

实现只有局部累加状态和只读表，不持有输入、不申请动态缓冲区，也不修改共享 CRC 外设。并发调用不共享可变累加状态，但调用方必须保证输入在计算期间不被并发修改或失效；ISR 使用还需自行评估帧长度、查表存储访问与执行时长，源码没有给出实时性保证。

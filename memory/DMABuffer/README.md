# DMA Buffer

`memory::DMABuffer<N, Alignment>` 提供固定容量的内嵌字节存储，供驱动借用，不负责启动或管理 DMA。cpkg 包名为 `memory::DMABuffer`，无包依赖；C++17 入口为 [dma_buffer.hpp](dma_buffer.hpp)，清单见 [cpkg.toml](cpkg.toml)。本包随宿主工程集成，不独立构建。

## 存储与生命周期

- `N` 必须大于零，`size()` 只返回可用字节数；默认对齐为 32 字节，也可显式指定编译器支持的合法 `Alignment`。`sizeof` 可能因对齐填充大于 `N`，不能按 `N` 推算多个对象的实际占用。
- 存储属于实例自身，类型禁止复制和移动。`data()` 及隐式字节指针转换取得的都是借用指针；实例必须持续存在，直到 DMA、驱动及其回调都不再访问该区域。
- 本类型自身不申请堆内存，但实例放在哪里由声明方式和外部容器决定，名字不保证整个调用链无动态分配。它不构造业务对象，也没有清空、重置或同步接口。
- 成员存储默认零初始化；自定义 section 的启动初始化仍由宿主提供。放入 `NOLOAD` 区域不能据此假定上电内容为零。

## DMA 与缓存职责

对齐只约束地址，不保证该地址对目标 DMA 可达，也不保证不可缓存或 cache-coherent。宿主负责链接脚本、实例所在 RAM、DMA 可达性、MPU/Cache 属性、传输长度与地址限制，并按芯片及驱动要求完成 cache clean/invalidate 和 CPU/DMA 所有权交接。

本包不访问 HAL、不校验地址、不配置硬件，也不提供锁或内存访问仲裁。即使实例满足 32 字节对齐，CPU、ISR 与 DMA 仍不得在未约定的时序下并发修改同一区域；驱动持有指针期间也不能销毁实例或另作他用。具体缓存操作范围必须考虑实际缓存行与相邻数据，不能仅由 `size()` 推定安全性。

# Static Object

`memory::StaticObject<T>` 为一个延迟构造、长期存活的对象预留固定地址存储。cpkg 包名为 `memory::StaticObject`，无包依赖；C++17 入口为 [static_object.hpp](static_object.hpp)，清单见 [cpkg.toml](cpkg.toml)。随宿主工程集成，不独立构建。

## 构造与访问

- 槽应具有静态存储期。`T` 必须是完整、具体、非数组且无顶层 `const`/`volatile` 的对象类型，不要求可默认构造、复制或移动。槽自身也不可复制或移动。
- 在函数体内用 `INIT_OBJECT(slot, 参数...)` 原地构造，宏返回 `T*`，不属于 `memory` 命名空间。严格 C++17 下无参形式写作 `INIT_OBJECT(slot, );`；参数直接用于 `new T(...)`，可包含裸花括号初始化列表。
- 每个槽只能成功构造一次。重复构造仅有 Debug 断言保护，Release 由调用方保证。构造异常原样传播，成功后才设置初始化标志；失败时槽仍未初始化。
- 用 `if (slot)`、`static_cast<bool>(slot)` 或与 `nullptr` 比较查询状态。当前头文件没有可调用的 `is_initialized()` 方法；不要把注释中的名字当作接口。`bool ready = slot` 可能经过隐式指针转换，应使用显式布尔转换保存状态。
- `->`、`*` 和隐式指针转换不做状态检查，只能在构造成功后使用。const 槽视图提供 const 访问；返回指针不拥有对象，禁止 `delete`。

## 永久对象与资源责任

存储按 `alignas(T)` 对齐，槽占用包括对象存储、内部状态和对齐填充。槽不自动调用 `T` 的析构函数，也没有销毁、清空或重新初始化接口，适合覆盖使用期的永久对象，不适合作为普通作用域 RAII 对象的替代品。对象所借用的驱动、缓冲区及其他资源必须覆盖其实际使用期。

槽自身只提供原地存储；`T` 的构造与运行仍可能分配内存、访问硬件或抛出异常，不能由 `Static` 名称推出完整无分配保证。实例的内存区域由宿主声明和链接脚本决定，本类型不配置 DMA、MPU 或缓存属性。

没有线程或 ISR 同步，也没有原子发布协议。应在任何使用者启动前完成初始化，或由调用方保护初始化、状态读取与对象访问；固定地址不能代替并发互斥或对象自身的线程安全。

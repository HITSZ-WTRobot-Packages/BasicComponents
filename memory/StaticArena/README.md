# Static Arena

`StaticArena<Size>` 是内嵌固定存储的线性分配器，适合一批对象共同存活、整体回收的场景，不提供逐块释放。cpkg 包名为 `memory::StaticArena`，无包依赖；C++17 入口为 [static_arena.hpp](static_arena.hpp)，清单见 [cpkg.toml](cpkg.toml)。注意类型实际位于全局命名空间，不是 `memory::StaticArena`。随宿主工程集成，不独立构建。

## 分配与对象生命周期

- 使用正的 `Size`。`allocate(size, alignment)` 返回借用的原始存储；容量不足返回 `nullptr`。`create<T>(args...)` 分配后 placement-new 构造，容量不足同样返回 `nullptr`。
- 缓冲区属于 arena，禁止复制。arena 必须覆盖所有分配结果及其使用者的生命周期，指针不能交给 `delete` 或普通堆释放函数。
- `create` 不捕获构造异常，异常传播时已推进的分配位置不会回滚。构造出的 `T` 自身仍可能分配堆内存；本包不是完整调用链的无分配保证。
- arena 不记录已构造对象，也不自动调用其析构函数，包含 arena 自身销毁时。需要释放对象资源时，由调用方在对象仍有效时显式完成析构或业务清理。
- `used()` 是包含对齐空隙的当前分配偏移，`capacity()` 是 `Size`；状态查询只是原子快照，不预留容量。

## 对齐与参数边界

内部缓冲区只保证 `alignof(std::max_align_t)` 对齐。偏移的取整公式要求 `alignment` 为非零的二次幂，且请求大小、偏移与取整运算不能发生 `size_t` 溢出；实现没有验证这些条件。不要依赖它支持超出缓冲区基址保证的过度对齐类型，`create<T>` 也不会额外验证这一点。零大小请求没有独立对象存储保证，不应用于获得唯一对象地址。

## 清空与并发边界

`clear()` 仅把偏移归零，不清零字节、不调用析构，也不保留旧分配的有效性。调用前必须结束所有旧指针的使用并完成必要清理，同时停止分配、构造及其他相关访问；之后旧指针在逻辑上全部失效，不能因为地址没变就继续使用。

CAS 只保证并发分配成功者取得不重叠的有效存储范围，不保护构造函数、对象内容或共享外设，也不发布业务数据。并发 `clear()` 会破坏旧分配和在途构造的生命周期，不能当作安全的并发回收。原子类型是否无锁及 ISR 使用是否合适取决于目标实现，本包没有锁自由或 ISR 时序保证；内存区域、DMA 可达性与缓存维护也由宿主负责。

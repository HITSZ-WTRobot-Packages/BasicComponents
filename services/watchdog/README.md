# Watchdog

`service::Watchdog` 是由调用方推进的软件存活计数器，不操作 STM32 IWDG/WWDG、不产生硬件复位，也不创建线程或定时器。cpkg 包名为 `services::Watchdog`，清单未声明包依赖；入口为 [watchdog.hpp](watchdog.hpp)，实现为 [watchdog.cpp](watchdog.cpp)，清单见 [cpkg.toml](cpkg.toml)。随宿主工程集成，不独立构建。

## 推进与超时含义

- 实例初始计数为 0，`isFed()` 为 false。`feed()` 把计数设为 `WATCHDOG_SNACKS`，当前为 10；`feed(snacks)` 设置指定值，并非累加。
- 每次 `eat()` 减一；静态 `Watchdog::EatAll()` 对全局已登记实例各执行一次 `eat()`。宿主选择唯一、稳定的推进来源，例如周期任务；计数单位是推进次数，不是毫秒，不读取系统时钟。不推进就不会随实际时间自动过期，重复推进则缩短存活期。
- `isFed()` 只判断计数是否大于 0，没有过期回调、事件通知或自动恢复。上层负责查询、检测有效到过期的转换，并在合适上下文执行断链处理、安全动作或硬件喂狗决策。
- 自定义喂食量会转成 `int32_t`，应使用 `1..INT32_MAX`；0 不表示存活，不要依赖超范围转换结果。递减不会在零处饱和，已过期实例仍持续消耗计数，因此也不是永久锁存的故障标记。

## 注册与生命周期

构造自动向固定全局表追加登记，默认 `MAX_WATCHDOG_NUM = 64`。该宏必须在编译实现与所有使用者时保持一致。表满时构造仍完成，但实例不被统一递减，也没有单实例注册成功返回值；此时即使喂食后 `isFed()` 为 true，也不代表它受到 `EatAll()` 监控。应在初始化阶段控制实例总数，`isFull()` 只反映当前全局数量，不能当作并发预留槽位。

析构函数不注销，全局表不会复用槽位。已登记对象必须持续存活到最后一次全局扫描结束，通常应作为系统长期对象；销毁后继续 `EatAll()` 会访问悬空指针。不要反复创建/销毁临时 watchdog 来做一次性超时。

## RTOS 与 ISR 边界

计数的 store/load/fetch-sub 是 relaxed 原子操作，避免单个计数访问撕裂，但不发布被监控对象的数据，不代替业务资源互斥。喂食与递减交错时，结果取决于实际原子操作先后；不能要求一次并发喂食必然保留完整计数周期。

全局表指针不是原子发布，构造先增加数量再写入指针；必须在开始 `EatAll()` 前完成登记，并由宿主避免登记、扫描与对象销毁交错。没有 RTOS 锁或线程归属检查。应只设置一个扫描来源；是否可在 ISR 使用还取决于目标原子实现是否无锁及平台约束，本包不承诺 ISR 可用性、扫描耗时或精确超时调度。

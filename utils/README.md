# Shared Utils

根级 `utils` 包提供 Cortex-M 中断临界区和简短忙等延时，不是 `libs/utils` 下各工具包的统一入口。cpkg 包名为 `utils`，依赖 `stm32cubemx`；清单见 [cpkg.toml](cpkg.toml)。入口分别是 [isr_lock.h](isr_lock.h) 与 [utils.h](utils.h)，随宿主工程集成，不独立构建。

## 中断状态保存与恢复

`isr_lock()` 读取当前 PRIMASK，调用 `__disable_irq()`，返回原始值。`isr_unlock(saved)` 先执行 `__DSB()`、`__ISB()`，再用 `__set_PRIMASK(saved)` 恢复保存值，不是无条件开中断。按后进先出顺序配对即可保留外层临界区的关闭状态；不能传入猜测值、复用别次保存值，或在不同执行上下文中配对。

C++ `ISRGuard` 在构造时保存并屏蔽，在作用域退出时恢复，禁止复制和移动。当前 `isr_lock.h` 的 `extern "C"` 未用语言宏保护，因此该头文件实际应由 C++ 翻译单元包含，不能因 `.h` 后缀就假定可直接作为 C 头使用。CMSIS 编译器头与相应 Cortex-M 指令支持由宿主提供。

适用于裸机或 RTOS 中很短的本核临界区；在 ISR 中使用也只保存/恢复进入时的 PRIMASK，不能把它当成改变异常优先级的工具。临界区内不应阻塞、等待依赖中断的事件或执行长操作，否则会延迟可屏蔽中断及依赖它们的调度。

PRIMASK 不屏蔽 NMI/HardFault，也不停止 DMA、其他总线主设备或其他核；本包没有线程 mutex、RTOS 临界区协议、跨核锁或 cache 所有权管理。只对依赖本核可屏蔽中断的访问时序提供保护，不能据此宣称任意线程、ISR 与 DMA 之间已互斥；内存屏障也不会自动完成缓存维护。

## 忙等延时边界

`utils.h` 从宿主 `main.h` 获取平台定义，`delay_us(us)` 用 `SystemCoreClock / 4000000 * us` 估算循环次数，再执行 ARM `subs/bne` 忙等。它占用当前上下文、不让出线程；时钟值必须正确，指令时序、代码/数据存储与中断都会影响实际延迟，不能用于精确定时或长期等待。

乘法是 32 位运算且没有溢出检查；调用方应保证估算结果非零且不溢出。特别是 `us == 0` 或估算截断为零时，循环仍先减一并回绕，不能把零当成无操作。该函数不校验参数、不自动屏蔽中断，也不初始化计时外设；ISR 使用会延长中断占用时间。
